# AI 仓鼠洞 · 3D 与交互改版研究

研究日期：2026-09-08。研究对象：AI 新手引流入口；核心转化地址为 <https://ai.alexdbg.com/>。

本文记录参考来源与设计决策。**“建议”不是已上线功能，最终完成范围以本次版本报告与代码为准。** 官网说明、页面可提取的控件与创作者项目介绍用于事实核实；未把动态网站的文本抓取当作逐帧体验测试，也未把参考站获奖视作转化率证据。

## 对现有版本的判断

依据 `brand-spec.md`、`web/src/App.tsx`、`web/src/scene/Scene.tsx`：当前方向是温暖的学习手册，3D 仓鼠承担向导角色，前景依次说明价值、Alex 经历、学习路线。场景只有仓鼠与接影地面，镜头通过 7 个摄影位多次左右摆动；角色的反馈主要是循环上下浮动和转身，桌面指针只影响镜头。首屏文案离场使用渐隐与最多 14 px 模糊。

这次值得升级的重点是：给仓鼠一个可读的微缩世界，让每次镜头变化对应一件具体的事，并让用户的动作得到即时角色反馈。材质精细度、光照层次、交互因果关系应共同改善，不能只增加面数、粒子与后期效果。

## 7 个可核实来源与取舍

| 来源 | 核实到的事实 | 本项目建议借鉴 | 本次不采用 |
| --- | --- | --- | --- |
| [1. Bruno Simon 个人作品集](https://bruno-simon.com/) | 页面明确邀请访客驾驶探索；有键盘、触屏、手柄说明，以及画质、静音、重生等选项。 | 把“操作 → 世界回应”做成容易发现的短反馈：摸摸仓鼠，仓鼠弹跳／转头；操作通过普通 HTML 按钮同样可达。 | 不把驾驶、寻找入口、累计成就设为阅读和进入学习站的前置条件。引流站需要快速理解价值。 |
| [2. Choo-Choo World](https://choochooworld.com/) | Lusion 制作的木质火车轨道搭建世界；有编辑／观赏切换、日夜设置、撤销、播放控制、图片下载，且支持触屏操作。 | 温暖的玩具尺度、圆润倒角、可辨识的小道具；用户选择一条学习路线，场景里对应路标或轨道亮起，形成“我做了选择”的归属感。 | 不搬入完整编辑器、两指转场手势或横竖屏锁定。四条学习路径不需要沙盒建造成本。 |
| [3. Lusion · Devin AI 案例](https://lusion.co/projects/devin_ai/) | 制作方将目标描述为清晰、易接近地解释复杂 AI 产品，运用故事、动画与互动展示功能。 | 每一段画面只承担一个传播任务：初见仓鼠 → 为什么相信 Alex → 选一条路线 → 进入学习站。功能文案保持真实 HTML。 | 不让难读的 3D 文字、连环过场或大段技术术语盖过“适合谁、能学什么”。归档演示站抓取超时，未声称测量其实际动画参数。 |
| [4. Lusion · Porsche: Dream Machine](https://lusion.co/projects/porsche_dream_machine/) | 官方案例是受委托制作的 CG 短片，以四阶段呈现跑车演进；它不是实时交互网页案例。 | 借鉴“少数关键画面构成旅程”的分镜方式，以及清晰主体、材质与光影组织。用四个内容阶段组织本项目叙事，首屏与 Alex 区共用探索舱。 | 不把影片的渲染复杂度、播放节奏或 16K 展示规格照搬进实时网页。 |
| [5. Active Theory · XR Experiments](https://xr.activetheory.net/) | 官方索引说明了 PBR、烘焙与实时光照、可复用辉光模块，以及面向移动硬件的后期优化。主页仅返回 JavaScript 壳；本项基于可检索的官方实验说明。 | 用眼睛、金属细节、屏幕、哑光身体之间的材质区别提升真实感；氛围主要由主光、轮廓光和反射完成。把光效设计成可降级模块。 | 不为普通引流页引入 XR、手势追踪、重粒子模拟或全屏体积特效；未将这些实验描述为本次实际运行验证。 |
| [6. Drei · AdaptiveDpr 官方文档](https://drei.docs.pmnd.rs/performances/adaptive-dpr) | 文档说明可以在性能回退状态按 Canvas 配置降低像素比，用暂时降低画质交换性能。正文打开遇到站点内容大小限制；官方搜索索引已核实此机制。 | 给 DPR 设上限，必要时减少像素密度；移动端减少阴影与装饰负担。先保交互响应，再决定渲染开销。 | 不声称降低 DPR 可以解决高面数、draw call 或 React 更新问题；也不承诺未经真机测量的帧率。 |
| [7. W3C · C39 减少动态效果技术](https://www.w3.org/WAI/WCAG22/Techniques/css/C39) | W3C 说明通过 `prefers-reduced-motion` 抑制非必要动画，并给出启用系统设置后检查动画被抑制的测试步骤。 | 页面与 WebGL 都响应减少动态效果：停止持续漂浮、指针视差、镜头穿梭、卡片倾斜，保留状态和导航。 | 不只给 CSS 添加一个媒体查询而让 Canvas 继续运动；不把“降低一点幅度”当作所有场景的充分替代。 |

## 确定画面：精细仓鼠探索舱

确定采用浅鼠尾草 `#e9eee5`、深墨绿 `#25382e` 与原品牌橙 `#e7634d`。仓鼠成为微缩探索舱里的主角：保留眼镜识别特征，增加圆润身体、清楚的鼻口与腮部结构、具有厚度的耳朵、双层眼球高光、独立前爪、少量可读的胡须。环形舱门、分层基座与悬浮学习道具讲清“学习与创造”，避免在主体周围堆满无关装饰。

建模时优先保住三个距离的阅读：远看有清楚剪影，中看能辨识仓鼠和探索站，近看可见材质、轮廓倒角与小道具。细节从眼睛、耳朵、爪子和道具接缝开始；毛感可用颜色层次或烘焙细节表达，不建议为浏览器增加数万根独立毛发。模型源文件、导出脚本与 GLB 一并留存，让改版可以重复生成。

首屏构图保留明显文字安全区。Hero 与 About 共享固定在右侧的 3D 探索舱；桌面上文字约占 45%，3D 约占 55%；手机可把角色与门洞的局部放在首屏标题附近，主体不需要完整塞进每一帧。学习区转入深色，使用四个可键盘选择的 tab 与即时内容面板。大标题、短说明、主入口始终比装饰信息更重要。

## 推荐交互编排

| 阶段 | 画面与动作 | 用户得到的反馈 | 对应目的 |
| --- | --- | --- | --- |
| 01 初见 | 仓鼠在探索舱前，轻呼吸，暖色灯光；提供“摸摸仓鼠”“转一圈”“日夜模式”按钮。 | 轻跳、受控旋转、灯光变化分别响应三个动作；反馈结束后回到稳定姿态。 | 首次操作几乎无学习成本，让角色有性格，并能欣赏新模型细节。 |
| 02 认识 Alex | 保持探索舱在右侧，镜头轻微换位；五段经历改为五项可展开内容。 | 展开项有清楚状态；镜头不随着每一行文字反复来回摆动。 | 缩短阅读距离，同时保留全部资历与经历信息。 |
| 03 选择路线 | 四个可键盘选择的 tab 对应即时内容面板，保留四组共 16 条学习内容与链接。 | 选中态、标题、适合人群与四个内容入口同步更新；同一页无需横向长距离滚动。 | 用户能判断哪条路径适合自己。 |
| 04 进入 | 深色学习区与最终主行动入口形成收束。 | 按钮有轻量按压反馈，点击直接新窗口进入学习站。 | 把注意力收回到清楚的下一步。 |

滚动保持浏览器原生行为。动画读取滚动进度，不通过拦截 wheel 事件接管滚轮；Hero 与 About 之间只安排必要的轻微镜头过渡。移动端 tab 与内容自然排版，按钮无需 hover 才能理解或使用。

## 动效参数建议

以下数值是为本项目提出的起始调校值，不是从参考站逆向测量的参数。

| 元素 | 建议起点 | 减少动态效果／触屏处理 |
| --- | --- | --- |
| 镜头阻尼 | `alpha = 1 - exp(-5 * delta)`，避免依赖显示器帧率；Hero 与 About 转场的小段进度用于换位，其余留给阅读。 | 减少动态效果时固定摄影位；触屏不应用指针视差。 |
| 首屏进场 | opacity + 12–20 px 位移，500–700 ms，最多 60 ms 顺序间隔。 | 直接显示或仅 120 ms 淡入；首屏 CTA 不等待长过场。 |
| 角色呼吸 | 周期 4–5 s；垂直位移不超过可见角色高度的 0.5%–1%。 | 停止。 |
| 眨眼 | 间隔 4–7 s，闭合／张开总计约 150 ms；左右眼统一。 | 停止循环；静态开眼。 |
| 指针反馈 | 角色头部最多约 5°–7°，镜头视差最多约 2% 画面宽度，180–250 ms 回应。 | 仅 `hover: hover` 且精确指针时开启。 |
| 摸摸／轻跳 | 总长 650–850 ms；100 ms 轻压，250 ms 上升，其余回落；缩放幅度不超过 4%，冷却约 900 ms。 | 用文案与短颜色变化反馈，避免位移和缩放。 |
| 转一圈 | 一次 360°，1400–1800 ms，起止减速；旋转进行时重复点击不无限叠加。 | 用静态角度切换或状态文字替代连续旋转。 |
| 日夜切换 | 背景、灯光和装饰亮度共同在 500–700 ms 完成过渡，文字对比保持清楚。 | 即时切换；保持按钮可读的开关状态。 |
| 路线切换 | 选中边框与底色 180–220 ms；内容淡入 200–300 ms，面板高度尽量稳定。 | 直接切换选中态；保留明确文字描述。 |
| 卡片悬停 | 上浮最多 4 px 或倾斜最多 2°，180–220 ms；二者不必叠加。 | 触屏及减少动态效果不倾斜；键盘 focus 有清楚边框。 |
| 主按钮 | hover 上浮 2 px；按下 scale 0.98；反馈 120–180 ms。 | 用颜色和边框回应；点击导航不等待动画结束。 |
| 微尘／轨道 | 若使用，限少量背景装饰，运动周期 12 s 以上，低对比。 | 停止；移动端优先删减。 |

## 验收与留痕建议

1. **画面对比**：旧、新版本使用相同浏览器视口、相同首屏／Alex／路线／末屏位置截图；保存截图文件名、视口、版本提交。不要把不同位置的截图当作同场景比较。
2. **动效对比**：录制同一条操作路径：停留首屏 → 指针移动 → 摸摸与转一圈 → 日夜切换 → 展开经历 → 切换两条路线 → 到最终入口。明确旧版没有哪些交互；用独立录屏或前后并排展示。
3. **交互验收**：键盘可按序到达按钮与链接；路线的选择状态可读；触屏无需 hover；减少动态效果时 Canvas 与 DOM 都停止非必要运动；断开 WebGL 或模型加载失败后仍能阅读和点击进入。
4. **性能记录**：记录 GLB 文件大小、几何统计、实际测试设备与浏览器。桌面先以 DPR 1–1.5、移动以 DPR 1 起测。任何帧率、首次加载时间或转化提升都要以实测为准。
5. **历史留存**：保留旧模型、Blender 源文件与旧版截图；新增版本说明并提交 Git；写清新增、替换、已验证与尚未验证事项。研究参考链接只用于解释设计依据，不等同于借用网站素材。

本轮设计的展示重点应是“仓鼠更精细、空间更完整、反馈更有因果、阅读和进入更顺畅”，而不是单纯统计增加了多少动画。
